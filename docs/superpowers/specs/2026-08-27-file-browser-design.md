# 局域网文件浏览器（视频为主）设计文档

日期：2026-08-27
状态：已批准

## 1. 目标

一个简单页面，把本机多个可配置目录里的文件展示出来，供局域网内设备（手机、平板、电视、其他电脑）访问：在线播放视频、在线查看图片、下载其他文件。支持搜索、排序、筛选和视频播放进度记录。

## 2. 技术选型

- 后端：FastAPI（Python）
- 前端：单个 `index.html`，内嵌 Vue 3（CDN 全局构建），手写 CSS，无构建步骤
- 数据库：SQLite（仅存播放进度）
- 配置：`config.json`（要展示的目录列表）

## 3. 架构

一个 FastAPI 应用（`app.py`）承担全部职责：

- 提供 REST API（文件列表、流式传输、播放进度）
- 托管静态页面（访问根路径直接打开页面）
- 监听 `0.0.0.0`，局域网通过 `http://<电脑IP>:8000` 访问

文件列表**递归扫描**（`os.walk`）配置的根目录及其所有子文件夹，抓取全部文件，不做全量入库。扫描结果在内存中做 **TTL 缓存（15 秒）**：列表请求命中缓存直接返回，过期后重新扫描；既保证文件变化最多 15 秒内反映到页面，又避免每次请求都全量遍历磁盘。

### 文件标识

每个文件用「根目录 + 相对路径 → SHA1 前 16 位」生成稳定 id（含根目录可避免多个配置根目录下相对路径相同导致 id 冲突、串文件）。不依赖文件内容，文件存在即可继续续播。

## 4. 配置（config.json）

```json
{ "dirs": ["D:\\迅雷下载\\other1"] }
```

- 首次运行若无配置文件，自动生成模板 `{ "dirs": ["D:\\迅雷下载\\other1"] }`（以用户实际目录为例）
- 修改配置后重启服务生效

## 5. SQLite 数据模型

表 `progress`（播放进度）：

| 字段 | 类型 | 说明 |
|---|---|---|
| file_id | TEXT PRIMARY KEY | 根目录 + 相对路径的 SHA1 前 16 位 |
| position | REAL | 上次播放到的秒数 |
| updated_at | REAL | 更新时间（unix 时间戳） |

## 6. API 设计

### GET /api/files

文件列表，支持以下查询参数（均可选）：

| 参数 | 取值 | 说明 |
|---|---|---|
| dir | 配置的根目录 | 只看某个根目录 |
| search | 任意字符串 | 文件名模糊匹配（大小写不敏感） |
| type | all / video / image / other | 类型筛选；**all = 视频+图片**（默认） |
| sort | name / size / mtime | 排序字段，默认 name |
| order | asc / desc | 排序方向，默认 asc |

返回（全部根目录、全部子文件夹的结果**混合在一起**，排序作用于整个结果集）：

```json
[
  {
    "id": "a1b2c3d4e5f6a7b8",
    "name": "movie.mp4",
    "size": 123456789,
    "mtime": 1724745600,
    "type": "video",
    "dir": "D:\\迅雷下载\\other1",
    "path": "sub\\movie.mp4"
  }
]
```

- `type` 判定：视频扩展名（mp4/mkv/webm/avi/mov/m4v/ts/rmvb/flv/wmv/mpeg）→ video；图片扩展名（jpg/jpeg/png/gif/webp/bmp/svg/avif）→ image；其余 → other
- `path` 是相对根目录的完整相对路径（含子文件夹层级），前端展示用
- 视频和图片**混合在同一个结果集**中，按 sort/order 统一排序，不按目录分组
- 空结果或文件不存在：返回空数组，不报错

### GET /api/file/{id}/stream

流式传输文件，**支持 HTTP Range 请求**（`FileResponse` 原生支持）。

- 视频 → `Content-Type: video/*`，浏览器 `<video>` 直接播放，可拖动进度条
- 图片 → `Content-Type: image/*`，浏览器直接显示
- 其他 → `Content-Disposition: attachment`，触发下载
- 加 `?download=1` 强制下载（视频/图片也可用）
- 文件不存在 → 404

### GET /api/progress/{id} / PUT /api/progress/{id}

读/写播放进度。

- GET 返回 `{ "position": 123.5 }`；无记录返回 `{ "position": 0 }`
- PUT 请求体 `{ "position": 123.5 }`，upsert 写入，更新 `updated_at`
- 文件 id 不存在也允许写入（不校验文件存在性）

### GET /api/dirs

返回配置中的目录列表：

```json
{ "dirs": ["D:\\迅雷下载\\other1"] }
```

## 7. 前端页面（index.html）

深色主题，观影场景舒适。布局：

```
┌────────────────────────────────────────────┐
│  🎬 文件浏览器     [目录▾] [🔍搜索……]      │
│  [全部|视频|图片|其他]  排序▾              │
├────────────────────────────────────────────┤
│  ┌──────┐ ┌──────┐ ┌──────┐               │
│  │ 封面  │ │ 封面  │ │ 封面  │  文件卡片网格  │
│  │ 名称  │ │ 名称  │ │ 名称  │   (视频+图片) │
│  └──────┘ └──────┘ └──────┘   混合展示     │
│  其他文件显示为图标行                        │
└────────────────────────────────────────────┘
```

### 交互

- **默认视图**：递归扫描到的所有视频和图片**混合在同一个卡片网格**中，按顶部排序规则统一排序（大小/修改时间/名称 × 升序/降序）
- **卡片**：显示格式图标 + 文件名 + 相对路径（如 `sub\movie.mp4`）+ 大小；视频卡片若有播放进度，显示「继续观看」角标。每张卡片都有下载按钮
- **视频**：点击卡片 → 右侧滑出播放器面板，原生 `<video controls>` 播放；打开时自动 seek 到上次进度；播放中每 5 秒静默 PUT 保存进度；播放结束（或进度 ≥ 95%）清空进度记录
- **图片**：点击 → 全屏灯箱预览，支持上一张/下一张（按当前列表顺序）
- **其他文件**：列表行展示，带下载按钮
- **顶部**：目录下拉切换、搜索框（输入即搜，300ms 防抖）、类型 Tab（全部/视频/图片/其他，默认「全部」= 视频+图片）、排序下拉（名称/大小/修改时间 × 升降序，作用于整个结果集）

### 浏览器兼容性

- 浏览器只支持 H.264/HEVC(mp4)、WebM、OGG 等编码；mkv/rmvb 等格式无法在线播放，卡片上标注「需下载后播放」（即前端只放 mp4/webm/ogv/mov/m4v 到 `<video>` 标签，其余视频卡片显示为「不支持在线播放」并只提供下载）

### 播放进度策略

- 每 5 秒保存一次（`timeupdate` 事件节流）
- 关闭/切换文件时立即保存
- 进度 ≥ 95% 视为看完，清空记录

## 8. 错误处理与边界情况

- **文件被删除/不存在**：stream 返回 404，前端播放器显示错误提示；列表是 TTL 缓存的，最多 15 秒内反映变化
- **目录不存在/不可读**：扫描时跳过该目录，日志告警；可读的子文件夹不受影响
- **扫描性能**：15 秒 TTL 缓存避免每次请求全量遍历；子文件夹数量极大的目录首次扫描可能稍慢，属可接受范围
- **浏览器不支持的视频编码**：卡片标注「需下载后播放」，仅提供下载
- **大文件流式传输**：FileResponse 支持 Range 和分块传输，不会把整个文件读进内存
- **并发访问**：SQLite 写操作用 `sqlite3` 默认连接，简单场景下加 `check_same_thread=False` + 每次操作独立连接（或线程锁），避免多设备同时访问报错
- **空状态**：无文件/搜索无结果时显示「没有文件」提示

## 9. 测试

- 手动验证：启动服务后
  - 列表加载、**子文件夹内的视频/图片也出现在列表中**、目录切换、搜索、筛选、排序正确
  - 视频在线播放 + 拖动进度条（Range 生效）
  - 播放进度续播 + 看完清空
  - 图片预览、灯箱翻页
  - 其他文件下载、视频/图片强制下载
  - 局域网其他设备访问正常
  - 删掉文件后页面不报错
- 用 `curl -H "Range: bytes=0-99"` 验证 Range 响应 206

## 10. 明确不做（YAGNI）

- 不做登录/鉴权（局域网内视为可信环境）
- 不做上传功能
- 不做视频转码（mkv 等格式直接下载看）
- 不做缩略图生成（视频封面用格式图标代替）
- 不做文件全量入库（TTL 缓存扫描足够）
- 不做子文件夹树形导航（文件平铺展示，卡片上显示相对路径）
